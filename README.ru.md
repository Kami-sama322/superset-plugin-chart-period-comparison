# Period Comparison (Сравнение периодов) — Chart-плагин для Apache Superset

Chart-плагин для **Apache Superset 6.1.0**: сравнение одной метрики за **до 5
произвольных периодов** на одном графике с относительной осью X, собственным
фильтром дат, который кросс-фильтрует весь дашборд, гибкой кастомизацией
линий и функциями вертикального масштаба.

![Period Comparison](images/thumbnail.png)

## Возможности

- **Свой фильтр дат на чарте** — 1–5 календарей (range picker) прямо на
  графике (дефолтные значения задаются в панели настроек). Изменение периода
  перезапрашивает сам чарт и эмитит кросс-фильтр.
- **Кросс-фильтрация** — фильтр дат эмитит одну клаузу `TEMPORAL_RANGE`,
  покрывающую span всех периодов (`min(start) : max(end)`), — остальные чарты
  дашборда фильтруются по сравниваемому окну времени.
- **Произвольные периоды одинаковой длины** — например, пн–пт этой недели и
  вт–сб две недели назад. Периоды разной длины блокируются валидацией.
- **Сравнение по** часам / дням / неделям / месяцам / кварталам / годам —
  гранулярность сравнения задаёт бакетизацию внутри каждого периода.
- **Относительная ось X** — линии выравниваются по позиции внутри периода
  («День 1…N»); в тултипе видны реальные даты каждой серии.
- **Corner cases** — количество недель/месяцев/кварталов считается от начала
  каждого периода (год по неделям даёт 52–53 бакета; короткие серии получают
  пропуски; пустые бакеты — разрыв линии, а не ноль).
- **Масштаб оси Y** — линейный, квадратный корень, логарифмический,
  квадратичный (power 2) — чтобы сгладить разницу больших и малых значений.
  Деления оси и подписи показывают исходные числа; логарифмическая шкала
  пропускает неположительные значения.
- **Кастомизация линий** — ломаная / сглаженная / ступенчатая
  (start|middle|end), область с прозрачностью, значения на узлах,
  экстремумы (min/max). Свёрнутые секции: **Line display** (толщина линии,
  значения на узлах, экстремумы, область) и **Scale, legend and zoom**
  (масштаб Y, легенда, слайдер зума, цвета сетки и осей — со сбросом на
  тему дашборда).
- **Маркеры и цвета по линиям** — в свёрнутой секции *Colors and labels*
  у каждой линии переключатель маркера (выкл / авто-форма / явная: круг,
  квадрат, треугольник, ромб, звезда — авто держит уникальную форму на
  линию), alias для легенды и цвет; очищенное поле = авто-значение. Там же
  размер маркеров и D3-формат чисел.
- Одна метрика, одна временная колонка — без разбивки по сериям (by design).

## Требования

- Apache Superset **6.1.0**
- Node.js 22 (сборка фронтенда Superset)
- Рантайм-зависимости плагина: `dayjs`, `echarts` (оба уже есть во фронтенде
  Superset)

## Установка в Superset (локально)

```bash
./install.sh /path/to/superset
cd /path/to/superset/superset-frontend
npm install
npm run dev-server
```

`install.sh` идемпотентен:

1. Копирует пакет в
   `superset-frontend/plugins/plugin-chart-period-comparison/`.
2. Регистрирует его в `src/setup/setupPluginsExtra.ts`
   (`key: 'chart_period_comparison'`).
3. Добавляет `file:`-зависимость в `superset-frontend/package.json`
   (якорь: `plugin-chart-word-cloud`).

Проверка: **Charts → + Chart → Period Comparison**.

## Настройка чарта

1. **Query**: метрика (одна), временная колонка, гранулярность *Compare by*,
   фильтры, row limit.
2. **Periods**: 1–5 диапазонов одинаковой длины (выбор по датам; последний
   день включается). Здесь задаются дефолты.
3. **Chart Options**: тип линии (для ступеней появляется Step position).
4. Свёрнутые секции-спойлеры: **Line display** (толщина, значения на узлах,
   экстремумы, область), **Scale, legend and zoom** (масштаб Y, легенда,
   зум, цвета сетки/осей), **Colors and labels** (маркер/alias/цвет по
   линиям, размер маркеров, формат чисел).

## На дашборде

- На тулбаре чарта — те же календари. Изменение диапазона перезапрашивает
  сам чарт (механизм `ownState`), остальные чарты получают span-фильтр.
- В Explore календари информационные — периоды настраиваются в панели
  настроек.
- Для работы span-фильтра включите **кросс-фильтрацию** на дашборде.

### Интеграция с датавыми фильтрами

Установите нативный фильтр
[`superset-plugin-filter-period-ranges`](https://github.com/Kami-sama322/superset-plugin-filter-period-ranges)
и добавьте его на дашборд (в скоуп чарта): чарт переходит под управление
фильтра — пикеры заменяются плашкой, диапазоны фильтра применяются к
собственной временной колонке чарта в его запросах. Пока в фильтре не
выбраны диапазоны, чарт показывает подсказку, а «Clear all» не возвращает
пикеры, пока фильтр существует.

Чарт также реагирует на **любой другой датовый фильтр**, дошедший до него
через агрегированный `extra_form_data` (calendar-фильтр, встроенный Time
range, клаузы `TEMPORAL_RANGE` от других чартов или простая клауза на
собственной временной колонке чарта): пикеры скрываются, но настроенные
периоды чарта сохраняются и сужаются этим фильтром — график рисуется, если
данные есть хотя бы в одном периоде. Под фильтром легенда называет
фактический диапазон каждой линии (период ∩ окно фильтра) — линия никогда
не подписана диапазоном, которого нет на графике.

Приоритет: structured-диапазоны period_ranges → любой применённый датовый
фильтр (свои настроенные периоды) → пикеры на чарте (ownState) →
конфигурация. Без датового фильтра в скоупе пикеры работают как раньше.

### Примечания по поведению

- Span-фильтр пересекается с дашбордными date-фильтрами (стандартная
  семантика Superset).
- Даты парсятся как UTC; бакеты считаются от начала периода, снэпнутого до
  границы гранулярности (недели начинаются с понедельника). Невозможные
  календарные даты отвергаются.
- Логарифм: значения ≤ 0 → пропуск; корень: значения < 0 → пропуск.
- Разная длина периодов блокирует применение фильтра (ошибка под тулбаром);
  минимум один пикер всегда остаётся.
- Цвета, не заданные в настройках, следуют теме дашборда — график читаем
  и в тёмной теме.

## Тесты

Jest-стиль `src/*.test.ts` (плоские `test()`), запуск внутри дерева
фронтенда Superset после `install.sh`:

```bash
cd superset-frontend && npx jest plugins/plugin-chart-period-comparison
```

Покрыто: парсинг/снэпинг/бакеты/валидация периодов, планирование запросов
(TEMPORAL_RANGE на период, маппинг гранулярности, общие фильтры),
выравнивание серий и масштабирование, сборка data-mask, дерево опций ECharts
(символы маркеров по сериям, оси, тултип), обвязка buildQuery.
